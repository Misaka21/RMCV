# 相机-IMU 时间同步标定工具

## 问题背景

相机和IMU（陀螺仪）是两个独立的传感器，各自维护独立的时间戳：
- 相机采集图像，记录拍摄时刻 `t_cam`
- IMU通过串口发送姿态数据，上位机记录接收时刻 `t_imu`

由于硬件延迟、传输延迟等因素，这两个时间戳**并不对齐**。

## 核心原理

利用**静止目标在世界坐标系下位置不变**的特性：

```
p_world = R_imu(t_cam - delta_t) * R_gimbal2imu * R_cam2gimbal * p_cam
```

通过找到最优的 `delta_t`，使得晃动云台过程中：
- 所有时刻转换到世界坐标系的点 `p_world` 方差最小（理论上应该完全重合）

## 符号定义（与 hardware_node.cpp 一致）

```cpp
// hardware/hardware_node.cpp:317
int64_t target_time_us = cam_time_us - delta_t_us;
```

- **`delta_t_us > 0`**: 图像比IMU数据**晚到达**，需要匹配**过去**的IMU
  - 例如：`delta_t_us = 5000` 表示图像实际对应 5ms 前的IMU姿态

- **`delta_t_us < 0`**: 图像比IMU数据**早到达**，需要匹配**未来**的IMU
  - 例如：`delta_t_us = -3000` 表示图像实际对应 3ms 后的IMU姿态

## 时间线示意图

假设 `delta_t_us = 5000`（正值，图像晚5ms）：

```
时间线 ───────────────────────────────────────────────►

IMU数据到达:        ●─────────────────────────────────
                   t_imu

相机图像到达:                        ●────────────────
                                    t_cam

                    └──── delta_t = 5ms ────┘

硬件节点匹配:       ●  ←── 查找这个时刻的IMU
              (t_cam - delta_t)
```

## 使用方法

### 1. 准备工作

- 将相机对准一个**静止的装甲板**或其他高对比度目标
- 确保装甲板在整个采集过程中都能被检测到
- 确保串口连接正常，能接收到IMU数据

### 2. 运行程序

```bash
cd /media/nuc11/common/RM/RMCV/RMCV2026/build
./3.test_time_sync
```

### 3. 开始标定

1. 按 `s` 开始采集（默认10秒）
2. **缓慢晃动云台**，确保yaw和pitch都有运动
   - 晃动幅度：yaw ±30°，pitch ±20° 即可
   - 速度不要太快，否则装甲板可能丢失
3. 采集结束后，程序自动标定

### 4. 查看结果

程序输出示例：

```
==================================================
相机-IMU 时间戳标定结果
==================================================
状态: 成功
信息: 标定成功
时间偏移: 5234.5 us (5.235 ms)
优化前标准差: 12.345 mm
优化后标准差: 1.234 mm
==================================================

请将以下配置写入 config/hardware.toml:
[TimeSync]
    delta_t_us = 5235

含义: 图像比IMU数据晚到达 5.2ms，匹配过去的IMU
```

### 5. 更新配置

手动编辑 `config/hardware.toml`，将结果写入：

```toml
[TimeSync]
    #@int 相机-IMU时间偏移 (微秒)
    # 正值: 图像比IMU数据晚到达，匹配过去的IMU
    # 负值: 图像比IMU数据早到达，匹配未来的IMU
    delta_t_us = 5235
```

## 评价标准

- **优化前标准差** > 5mm：数据采集质量良好
- **优化后标准差** < 2mm：标定成功
- **优化后标准差** 2-5mm：标定可用，但建议重新标定
- **优化后标准差** > 5mm：标定失败，请检查：
  - 装甲板是否静止
  - 云台晃动是否足够（需要yaw和pitch都运动）
  - 相机和IMU时间戳是否正确记录

## 故障排查

### 问题1: 采集过程中装甲板丢失

**原因**: 晃动速度过快，或装甲板离开视野

**解决**:
- 放慢晃动速度
- 减小晃动幅度
- 增加光照，降低曝光时间减少运动模糊

### 问题2: 优化后标准差仍然很大（>10mm）

**原因**:
- 目标不是静止的（如晃动的三脚架）
- 外参不准（R_gimbal2imubody 或 R_camera2gimbal）
- **IMU时间戳记录错误**（已修复）

**历史bug说明**：
v1 版本在队列处理时才记录 IMU 时间戳（`Clock::now()`），导致时间戳比实际接收晚 5-10ms。
v2 版本已修复，使用串口线程记录的 `data.recv_time_us`。

**解决**:
- 先标定外参（`1.test_gimbal2imubody` 和 `2.test_extrinsic_calib`）
- 更换更稳定的目标

### 问题3: 相机数据点不足

**原因**: 装甲板检测失败率高

**解决**:
- 检查检测器参数（`config/detector.toml`）
- 调整相机曝光和增益
- 选择更明显的装甲板

### 问题4: 标定出的 delta_t 符号与预期相反

**原因**: 相机和IMU的传输延迟差异大

- 相机USB传输延迟：~10-15ms（大图像）
- IMU串口延迟：~1-2ms（小数据包）
- 上位机记录的时间戳顺序可能与硬件产生顺序相反

**不影响标定**：只要算法内部符号一致即可，最终优化出的 `delta_t` 会自动适应实际延迟关系。

## 算法细节

### 粗搜索

在 `[-100ms, +100ms]` 范围内，以 `1ms` 步长暴力搜索最优 `delta_t`

### 精细优化

使用 Ceres 数值优化库：
- 代价函数：世界坐标系下点的标准差
- 数值微分计算梯度（因为SLERP不方便自动微分）
- 收敛条件：函数容差 1e-10

### IMU姿态插值

使用球面线性插值（SLERP）在相邻IMU数据间插值：

```cpp
q_interpolated = q0.slerp(alpha, q1)
```

其中 `alpha = (t - t0) / (t1 - t0)`
